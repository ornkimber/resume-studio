# Resume Studio — version 0.1

A local Tauri desktop application with a React/TypeScript editor and the existing
Python Word renderer. All implementation is contained in this folder. The original
scripts and resume files in the repository root are separate from this application.

## First version

- English and Chinese workspaces seeded with fictional John Doe and 陈大文 samples.
- YAML and TOML editing for both resume content and style configuration.
- Explicit format conversion; the original source is saved as a revision before
  conversion because comments do not survive conversion between formats.
- Live DOCX preview generated by Python, with the previous valid preview retained
  when an edit contains errors. HTML previews are approximate: final pagination
  must be checked in Word.
- Persistent drafts and named revisions containing content, styles, formats, and
  language. Compare source changes or render two versions side by side. Restoring
  a revision first saves the working draft as another revision.
- Parse and validation errors with field paths, plus line/column where available.
  YAML field errors have source locations; TOML field errors have paths. TOML
  syntax errors include positions when provided by the parser.
- Individual or batch DOCX export, source import/export, and workspace backup export.
- Original rendering functions for all five section types, CJK fonts, inline bold,
  headings, spacing, date tab stops, borders, and the internal style guide.

## Run locally

Development needs Python 3.11+, a supported Node.js LTS (22.12+ or 24+), npm, Rust,
Microsoft C++ Build Tools, and WebView2 on Windows. The packaged desktop app includes
its Python interpreter and libraries. Word is only needed for your subsequent PDF export.

```powershell
cd resume-studio
python -m pip install -r python/requirements.txt
npm.cmd ci
npm.cmd run desktop
```

The desktop command applies a development configuration without a packaged
sidecar; it calls the installed Python interpreter directly. A fresh clone does
not need PyInstaller to start live development.

For browser development with the same real Python engine:

```powershell
npm.cmd run dev
# Open http://127.0.0.1:1420
```

The browser transport is a Vite development plugin, bound to localhost. It is not
included as a server in the installed desktop application. `npm run preview` serves
only compiled assets and does not provide the Python transport; use `npm run dev`
for a functional browser session.

## Build a Windows installer

```powershell
python -m pip install -r python/requirements-build.txt
npm.cmd run desktop:build
```

The installer is written to `src-tauri/target/release/bundle/nsis/`.
The build first packages a headless Python engine, then bundles it with Tauri.
`src-tauri/target/release/resume-studio.exe` also runs from the build folder when
the adjacent `resume-engine.exe` is present. Prefer the installer for distribution.
This first version targets Windows; additional operating systems need their own
sidecar builds and native verification. The installer is not code-signed.

## Python CLI

```powershell
python python/engine.py --input fixtures/resume_en.yaml --config fixtures/style_config.yaml --lang en --output exports/english.docx
python python/engine.py --input fixtures/resume_zh.yaml --config fixtures/style_config.yaml --lang zh --output exports/chinese.docx
```

Both `--input` and `--config` also accept `.toml` files. The CLI prints one JSON
result and exits nonzero on failure. Output is written atomically after generation
and validation. It creates missing parent directories.

For Word PDF export, the existing helper is copied to `python/export_pdf_word.ps1`:

```powershell
.\python\export_pdf_word.ps1 -InputDocx exports/english.docx -OutputPdf exports/english.pdf
```

PDF conversion is a separate step in this version. Word or LibreOffice determines
final pagination; the embedded preview is not used to produce the DOCX or PDF.

## Storage and recovery

The desktop workspace is saved in Tauri's application data directory, normally
`%APPDATA%\org.resumestudio.desktop\workspace.json` on Windows. A
`workspace.backup.json` holds the preceding saved workspace. The native app flushes
pending edits before closing. Invalid existing workspace data is preserved and
automatic saving is disabled until it is recovered.

Browser development stores data in `.test-data/workspace.json`. Set
`RESUME_STUDIO_DATA` to a different directory to isolate development data. UI tests
use `.test-data/ui/` and never overwrite the ordinary development workspace.

Use **Export workspace backup** to save a portable JSON copy. To recover a backup,
close the application and replace `workspace.json` with the exported file. No
in-app backup import or revision deletion is included in this version. The
workspace has a 12 MB limit; individual source files have a 2 MB limit.

## Architecture and compatibility

- `src/`: React workspace, CodeMirror editors/diffs, DOCX preview, format conversion.
- `src-tauri/`: native dialogs, atomic file writes, workspace persistence, Python process bridge.
- `python/original_renderer.py`: an unchanged copy of the existing generator.
- `python/engine.py`: parsing, validation, JSON protocol, and orchestration of the
  original rendering functions. Each request runs in an isolated process with a
  60-second desktop timeout; logs never share stdout with the JSON response.
- `fixtures/`: fictional English/Chinese resumes and reference style settings.

The adapter deep-copies style configuration before language overrides, preventing
cross-language mutations. It also supplies the existing renderer's `_resume_cfg`
property so custom bullet marker/indent/font settings take effect (the original
entry point did not populate that property). The reference documents use the
original defaults, so their document, style, and numbering XML remains identical.
Parser validation deliberately rejects duplicate YAML keys and unsupported value
types; quote dates as strings in either format.

Dependency versions are pinned for Python and locked with `package-lock.json` and
`Cargo.lock`. Historical previews use the currently installed renderer version;
the revision records its originating engine version, but does not archive engines.

## Verification

```powershell
npm.cmd test
npm.cmd run test:ui
cargo test --manifest-path src-tauri/Cargo.toml
npm.cmd run build
```

Before running Cargo tests directly, install `python/requirements-build.txt` and
run `npm run engine:build`; the default native configuration includes that binary.

Python tests compare `word/document.xml`, `word/styles.xml`, and
`word/numbering.xml` byte-for-byte against the original renderer for both languages,
and cover malformed input, style overrides, custom bullets, and CLI failures.
TypeScript tests verify lossless YAML/TOML content conversion and workspace checks.
Playwright tests run the real Python engine in headless Microsoft Edge and exercise
editing, previews, revisions, comparisons, restoring, exporting, persistence,
errors, and source scrolling. Local runs use Microsoft Edge; CI installs and uses
Playwright Chromium. See the root README for CI and draft-release instructions.
